## Shape of the repo (post-rename)

- The library is `recall_guard/` (renamed from `src/`). **There is no top-level `src`
  package** — never reintroduce one. Internal imports are `from recall_guard.<layer> import …`.
- It is an installable distribution: hatchling build-system, `uv build` → wheel + sdist.
  `import recall_guard` works from an installed wheel with no source tree on `sys.path`.
- Python floor `>=3.12` (`.python-version` = 3.12). CI targets Python 3.12 and 3.14. Local validation on 2026-10-30 passed all 600 tests on native Windows
  Python 3.12.10 and 3.14.9, and through Dagger in Debian WSL on Linux Python
  3.12.12 and 3.14.2. GitHub-hosted jobs have not yet been run for these commits.
- Dependencies: lean runtime (`numpy`, `scikit-learn`, `rich`, `pyyaml`, `requests`,
  `python-dotenv`) + extras `backtest` (matplotlib, vectorbt) and `docs` (mkdocs stack) +
  `[dependency-groups] dev` (test/lint/notebook/docs tooling). uv installs `dev` by default,
  so `uv run pytest` works; consumers get only the lean runtime.

## Public API (what consumers import)

```python
from recall_guard import MemoryGuardedScorer

scorer = MemoryGuardedScorer.calibrate(
    api_key=...,                      # NVIDIA NIM key
    model="openai/gpt-oss-20b",
    is_memorized=[...],               # prompts dated before the model's cutoff
    oos_control=[...],                # prompts dated after it
    reference_model=None,             # optional → adds the ref_delta feature
)
g = scorer.score("any prompt")        # or scorer.score_many([...])
g.signal, g.p_memorized, g.memguard_confidence, g.features, g.fail_reason
scorer.holdout_auc, scorer.is_weak    # calibrator quality
```

- The façade lives in `recall_guard/harness/scorer.py` and **reuses the evaluator parser +
  MIA/MCS functions verbatim**, so `p_memorized` is bit-for-bit identical to the batch
  harness (a parity test enforces this — keep it green when touching either path).
- `ConfigurationError` is raised on a missing/empty key (at `calibrate`) and on a rejected
  credential / HTTP 401 (at calibrate or score). Timeouts / parse failures return a
  `GuardedScore` failure record instead.

## Invariants — do not regress

- **`import recall_guard` stays matplotlib/vectorbt-free.** `recall_guard/harness/__init__.py`
  lazy-loads the `plot_*` / `configure_paper_style` helpers via PEP 562 `__getattr__` (same
  pattern as `recall_guard/dataset/__init__.py`). The package root `__all__` re-exports **no
  `plot_*` symbol and nothing from `portfolio`**. A `sys.modules` subprocess test guards this
  — never add an eager `from …plots import` to harness `__init__` or the root.
- **Architecture and readability.** Preserve layering (`core` below
  `mia`, `dataset`, `portfolio`, below `harness`), no cycles and the `dspy` ban.
  Use `uv run python scripts/check_architecture.py`, Ruff and tests as gates.
  Sentrux is not required, per the user's instruction on 2026-10-30. Treat the
  existing complexity/length limits as review guidelines, not a tool dependency.
  Prefer focused idiomatic Python/NumPy and names that match domain meaning,
  representation and units. Document array axes and DataFrame row grain,
  column/index meanings and alignment. Windows users execute the application
  through Docker. Retain explicit UTF-8 text artifacts, portable diagnostic
  paths and shell-neutral Python entry points.
- **Renames touch strings too.** When moving modules, rewrite `recall_guard.<layer>`
  references inside string literals — `mocker.patch(...)` targets, `logger="…"` names, the
  `python -m …` CLI `prog`, error messages — not just `from … import` lines. A plain import
  sweep silently misses mock-target strings.

## Purpose framing — carry forward

recall_guard is **not a forecaster**. Near-coin-flip directional accuracy is the expected,
correct result; the product is the measured `p_memorized` honesty/contamination signal for
AI macro/risk factor analysis, not predictive alpha. Do not "fix" the eval prompts to chase
accuracy.

## Ensemble surface (v0.3.0)

- `ensemble-consensus` shipped: an **opt-in, per-call** N-draw path. No implicit default
  config, no env var, no process-wide toggle. Without an `EnsembleSpec` every existing
  surface is byte-for-byte unchanged.
- **Exception: the guarded-decision API is ensemble-first** (spec
  `memorization-adjusted-finance-sim`). `guarded_decide` runs the ensemble by default and
  draws once only on explicit request (`DrawMode.SINGLE`); such a result is labelled a single
  draw, carries no distribution and is not reported as the model's decision without that
  label. It never withholds or zeroes a decision on a single-draw estimate.
- The exception covers only that API. `MemoryGuardedScorer.score` and `score_many` stay
  single-draw, `score_ensemble` stays opt-in per call, and the scorer's single-draw
  `p_memorized` parity with the batch harness is unchanged (keep the parity test green).
- New `core` modules: `consensus.py` (pure statistics, stdlib only -- no numpy, no scipy)
  and `ensemble.py` (spec, wave executor, reduction, hashing). `MemoryGuardedScorer.score_ensemble`
  returns `EnsembledScore`.
- **`p_memorized_point` is the exposure multiplier**; `consensus.p_memorized` is evidence
  only. They differ by construction and the type documents which is which.
- The reduction is pure and order-free, so a stored draw set replays bit-identically. Every
  tie breaks on content alone. No RNG, so no seed is persisted.
- **Pacing contract changed**: `min_call_interval_s` now spaces request *starts* and is
  latency-independent. The lock no longer wraps the POST -- previously every concurrent call
  through one client serialised, even with pacing disabled, so `max_workers` was inert
  package-wide. CLI `--max-workers` default dropped 8 -> 1 so upgrading is not an 8x traffic
  event; **library defaults remain 8 and are now real**.
- **Generation settings belong on the spec** (`max_tokens`, `temperature`, default `None`).
  An ensemble drawn at a different token budget is not measuring the production decision --
  on a reasoning model the chain of thought eats the budget and truncates the payload.
  Downstream measured 48% vs 95% parse rate at 512 vs 2048. Both are recorded on the result.
- **`draws` sizes agreement precision, not split detection** -- two different numbers.
  `smallest_certifiable_n` covers the first, `smallest_detectable_split_n` the second.
  At the default 64, split detection misses ~3% of subsamples on the shipped corpus.
- **The sampled distribution drifts between sessions**, not only within one. Same prompt,
  same model id, two days apart moved one component's median materially while others held.
  So a consensus has a shelf life: `sampled_at` stamps execution (`None` on replay), stored
  corpora are not ground truth for a fresh run, and threshold tuning ages.
- Size split detection against `n_parsed`, not `draws` -- the test only sees replies that
  survived transport, parsing, and the caller's projection.
- `component_verdicts` reports the split test for **every** component, not only flagged ones.
- Detector thresholds are all provisional, tuned on one crisis-onset date, and all exposed on
  `EnsembleSpec` rather than frozen in source.

## Windows and pacing maintenance

Request admission waits under the pacing lock and records the actual wakeup time.
Network POSTs remain outside the lock so calls can overlap. This supersedes the
older reservation-based implementation described in the release history above.
Delayed wakeups must not compress subsequent starts.

## Endpoint-based divergence evaluation — 2026-11-01 scope amendment

### Local-provider scope split — 2026-11-05

Current work focuses on [local-ai-provider](../specs/local-ai-provider/requirements.md):
small local models, Gemma prioritized for NPU evaluation, mandatory observed log
probabilities, and explicit hardware/runtime feasibility. Opus and other frontier
APIs without logprobs remain a separate alternative path; they are not fallback
providers in this local spec. Treat the observed November 5 NIM attempts as
"NIM unavailable", retaining HTTP 504 receipts without assigning a root cause.
Optional local hosting does not make accelerator dependencies mandatory for the
library. This split supersedes any interpretation that local-provider delivery
must also implement the frontier completion-only experiment.

Divergence evaluation follows configured endpoints and statistical sources:
capability/evidence assessment, auxiliary provenance, development calibration of
correction strength, frozen configuration, and paired held-out measurement.
Full compatible log probabilities may substitute for raw logits; partial or
sample-estimated evidence must be labeled and validated as approximate.
Evidence sourcing and generation control are separate capabilities.
AUC measures discrimination, not correction calibration or mitigation efficacy.
Local model hosting/GPU capacity is not a project prerequisite. Do not resume
superseded runtime tasks or substitute rewriting for divergence decoding.
GPT-OSS-20B remains included; ensembles are separately reported and budgeted.
See [scope amendment](../specs/divergence-decoding-evaluation/scope-amendment.md).
